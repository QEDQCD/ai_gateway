# Admin 后台模型导航与新建弹窗设计

## 背景

当前 admin 控制台已具备：

- `后台模型` 页面：用于查看供应商与模型挂载关系
- `新建模型` 页面：用于创建供应商和模型
- `账单` 页面：用于查看租户账单

但当前交互存在三个问题：

1. 左侧导航顺序不符合常见后台使用习惯，`总览` 没有放在第一项。
2. `新建模型` 作为独立左侧子页面暴露，信息架构偏散，用户需要在“查看模型”和“创建模型”之间来回切换。
3. 用户已经反馈 `账单` 页面“不明显 / 没看见”，需要在保留页面的前提下优化左侧导航的可发现性。

本次只做 admin 前端信息架构和交互收敛，不涉及二期能力。

## 目标

- 将左侧导航的 `总览` 调整到第一项。
- 保留 `账单` 页面，并继续作为左侧可访问子页面。
- 移除左侧导航中的 `新建模型` 项。
- 将“新建模型”能力收敛到 `后台模型` 页面中，以“按钮 + 弹窗”形式承载。
- 弹窗中复用现有“新建模型”表单能力，不重做业务逻辑。
- 创建成功后关闭弹窗，并刷新 `后台模型` 页面列表。

## 非目标

- 不调整后端模型创建接口语义。
- 不新增二期能力，例如用户级调用监控、限流、employee 维度等。
- 不重做 `账单` 页业务逻辑，仅保证其导航可见性与顺序合理。
- 不删除现有 `/provider-model-create` 路由。

## 已确认决策

- `/provider-model-create` 路由继续保留，作为兼容入口。
- 兼容入口不再出现在左侧导航中。
- 本次改造优先控制风险，避免影响已可用的模型创建逻辑。

## 方案对比

### 方案 A：提取共享表单组件，在弹窗中复用

做法：

- 将当前 `新建模型` 页面的表单主体提取为共享组件。
- `后台模型` 页面增加 `新建模型` 按钮。
- 点击按钮后，在 modal 中渲染共享表单组件。
- 旧路由页继续复用同一份表单组件。

优点：

- 结构清晰，页面容器与表单逻辑分离。
- 后续若还需要独立页、抽屉、弹窗等不同承载方式，可继续复用。
- 样式与交互更容易统一。

成本：

- 需要对现有页面做一次小幅重构。

### 方案 B：在弹窗中直接嵌入现有页面

做法：

- 保持现有 `admin-provider-model-create` 页面不拆分。
- `后台模型` 页面按钮点击后，直接在 modal 中嵌入整个页面组件。

优点：

- 改动速度快。

问题：

- 页面与弹窗职责混杂，后续维护成本高。
- 容易出现布局、标题、间距、跳转逻辑重复问题。

## 结论

采用 **方案 A**。

原因：

- 本次改造的核心是收敛信息架构，而不是临时把页面“塞进弹窗”。
- 共享表单组件能够在不改业务语义的前提下，长期降低 UI 维护成本。

## 信息架构设计

### 左侧导航调整

admin 左侧导航调整为：

1. `总览`
2. `应用审批`
3. `租户`
4. `账单`
5. `API Key`
6. `调用观测`
7. `审计`
8. `后台模型`
9. `健康检查`

说明：

- `总览` 固定在第一项。
- `账单` 保留为独立左侧子页面。
- `新建模型` 从左侧导航移除。

### 后台模型页交互

`后台模型` 页面顶部增加主操作按钮：

- 按钮文案：`新建模型`

交互流程：

1. admin 进入 `后台模型` 页面。
2. 点击 `新建模型` 按钮。
3. 打开 modal。
4. modal 内展示当前模型创建表单。
5. 创建成功后：
   - 关闭 modal
   - 刷新当前模型列表
6. 创建失败时：
   - modal 不关闭
   - 保留错误提示与表单状态

## 组件拆分设计

建议拆分为三层：

### 1. 页面容器：`admin-provider-models`

职责：

- 获取并展示模型列表
- 承载顶部操作区
- 控制 modal 开关状态
- 在创建成功后重新拉取列表

### 2. 共享表单组件

职责：

- 承载“供应商 + 模型”创建表单
- 处理提交态、校验态、错误展示
- 暴露创建成功回调

要求：

- 不依赖“必须是整页路由”这一前提
- 可同时被：
  - `后台模型` 页弹窗
  - `/provider-model-create` 兼容页
  复用

### 3. 兼容路由页：`/provider-model-create`

职责：

- 作为历史入口保留
- 页面内容仅作为共享表单组件的轻容器
- 不在左侧导航展示

## 路由与兼容性

### 保留内容

- 保留 `/provider-model-create` 路由定义
- 保留其权限控制与页面访问能力

### 调整内容

- 将 `/provider-model-create` 从 `adminNavigation` 中移除
- 不再作为主路径向用户暴露

兼容收益：

- 已保存的浏览器书签不会立刻失效
- 现有测试、已知入口和历史访问路径风险更低

## 状态流转

### 打开弹窗

- 默认关闭
- 点击 `新建模型` 后设置为打开

### 提交中

- 提交按钮进入 loading
- 禁止重复提交

### 提交成功

- 触发成功提示
- 关闭弹窗
- 调用模型列表刷新

### 提交失败

- 保留弹窗打开
- 显示错误信息
- 允许用户修正后重试

## 测试设计

需要覆盖以下最小测试集：

### 路由 / 导航测试

- admin 左侧导航中 `总览` 位于第一项
- admin 左侧导航中可见 `账单`
- admin 左侧导航中不可见 `新建模型`

### 页面交互测试

- 进入 `后台模型` 页面可看到 `新建模型` 按钮
- 点击按钮后弹出 modal
- modal 中能看到创建表单关键字段

### 回归测试

- `/provider-model-create` 路由仍可访问
- 原有创建接口调用行为不变

## 风险与控制

### 风险 1：表单重构引入行为回归

控制：

- 只提取 UI 与提交逻辑公共层，不修改接口协议
- 保留兼容路由页，便于对照验证

### 风险 2：弹窗内样式错位

控制：

- 共享表单组件避免写死页面级宽度与标题布局
- 由容器页决定 modal 宽度和标题

### 风险 3：创建成功后列表未同步

控制：

- 将“关闭弹窗 + 刷新列表”绑定在成功回调中统一处理
