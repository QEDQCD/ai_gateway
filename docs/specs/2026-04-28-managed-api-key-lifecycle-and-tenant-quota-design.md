# AI Gateway 平台托管密钥生命周期与租户额度治理设计

> 日期：2026-04-28
> 状态：Draft for review
> 目标：把当前 API 密钥能力从“一次性展示的演示功能”升级为“可回显、可审计、可过期、可配额治理”的完整平台能力
> 适用范围：
> - 平台管理员 `admin`
> - 租户用户 `member`

## 1. 设计结论

本轮不再继续沿用“只存 hash、只能在创建瞬间复制一次”的密钥模式。

新的产品结论是：

1. 平台 API Key 属于“平台托管资产”
2. 平台必须支持“历史密钥受控回显”
3. 明文密钥必须以“服务端加密存储”方式保管，而不是明文落库
4. 鉴权仍然依赖 `key_hash`
5. 生命周期默认值固定为：
   - 有效期：`30 天`
   - 到期前告警期：`3 天`
   - 到期动作：`自动失效`
6. 配额默认绑定在“租户”层，而不是单密钥层：
   - 请求次数额度
   - Token 总量额度
7. 用户端必须可以直接查看：
   - 当前租户额度
   - 已用请求数
   - 已用 Token
   - 剩余额度
   - 重置时间
   - 自己创建的密钥明文

这意味着产品主线要从“创建一次然后手工记住密钥”升级为“平台持续托管密钥并治理租户消费”。

## 2. 已确认约束

以下边界已经明确，不再摇摆：

- 历史密钥：`平台可解密回显`
- 密钥用途：`平台分发给用户直接调用`
- 默认额度模型：`请求次数 + token 双限额`
- 默认额度绑定层级：`租户级`
- 历史明文查看权限：
  - `member` 只能看“自己创建”的密钥
  - `admin` 可以看平台内全部密钥
- 到期策略：`到期前 3 天预警，到期自动失效`

## 3. 问题定义

当前实现存在 4 个结构性问题：

1. 已选中历史密钥时，没有稳定的“查看 / 复制完整密钥”产品形态
2. 密钥只适合“一次性创建后马上复制”，不适合平台托管
3. 密钥没有完整生命周期：
   - 无默认有效期
   - 无即将过期状态
   - 无到期失效动作
4. 配额与消耗没有围绕“租户预算”形成闭环：
   - 用户拿到 key 之后，仍然看不到完整的额度关系
   - 控制台有调用观测，但没有“可治理的额度面板”

如果继续在现有结构上只补按钮和提示语，最后会得到一个行为上可用、产品上不完整的半成品。

## 4. 方案比较

### 4.1 方案 A：平台托管密钥 + 服务端加密存储 + 租户额度账本

核心：

- 明文密钥加密存储
- Hash 鉴权
- 历史明文受控回显
- 租户级双额度
- 生命周期状态机
- 审计日志闭环

优点：

- 安全边界与产品能力平衡最好
- 和当前 admin/member 架构最兼容
- 能直接体现“平台 API 分发与治理”

缺点：

- 需要补数据库字段、加密服务、回显接口和额度表

### 4.2 方案 B：把历史明文继续交给前端缓存

核心：

- 只在浏览器本地缓存已创建密钥
- 后端仍然不保留可解密密文

优点：

- 改动最小

缺点：

- 用户换设备或清缓存后就丢失
- 不满足“历史密钥可回显”
- 本质上仍是演示方案

### 4.3 方案 C：只允许轮换，不支持历史回显

优点：

- 安全性最保守

缺点：

- 与已确认需求冲突
- 用户体验差，不适合“平台给用户发密钥”的产品定位

### 4.4 推荐方案

采用 `方案 A`。

这是唯一既满足你的明确需求，又不至于把系统做成“明文裸奔后台”的方案。

## 5. 总体设计

系统拆成 4 个子域：

1. `密钥资产域`
   - 创建、轮换、停用、到期、回显
2. `密钥机密域`
   - 明文加密、解密、权限校验、回显审计
3. `租户额度域`
   - 请求次数额度
   - Token 额度
   - 周期重置
   - 超限判断
4. `控制台展示域`
   - member 自助查看和复制
   - admin 平台治理

设计原则：

- 明文密钥只在服务端受控解密
- 网关鉴权永远走 hash，不直接拿密文比对
- 额度拦截发生在网关链路
- 控制台展示依赖数据库沉淀，不依赖浏览器缓存

现有表扩展为：

- `id`
- `tenant_id`
- `name`
- `key_hash`
- `key_ciphertext`
- `key_kek_version`
- `status`
- `scopes`
- `created_by_user_id`

- `expires_at`
- `expire_warning_sent_at`
- `rotated_from_key_id`
- `disabled_at`

字段说明：

- `key_hash`
  - 鉴权使用
- `key_ciphertext`
  - 使用平台主密钥加密后的明文
- `key_kek_version`
  - 允许未来轮换加密主密钥
- `created_by_user_id`
  - 用于 member 级历史明文查看权限
- `expires_at`
  - 默认 `created_at + 30 天`
- `rotated_from_key_id`
  - 记录轮换链路，便于审计

### 6.2 `tenant_quota_policies`

新增租户额度策略表：

- `tenant_id`
- `effective_from`
- `period_type`
- `request_limit`
- `token_limit`
- `created_by`
- `created_at`
- `updated_at`

说明：

- `period_type` 第一版固定为 `monthly`
- 一个租户同一时间只有一条生效策略

### 6.3 `tenant_quota_usage_periods`

新增租户周期用量表：

- `tenant_id`
- `period_start`
- `period_end`
- `requests_used`
- `tokens_used`
- `last_aggregated_at`

作用：

- 支撑租户当前周期剩余额度查询
- 避免每次都扫明细表实时聚合

### 6.4 `api_key_secret_access_logs`

新增密钥明文访问审计表：

- `id`
- `api_key_id`
- `tenant_id`
- `actor_user_id`
- `actor_role`
- `action`
- `access_result`
- `ip_address`
- `user_agent`
- `created_at`

`action` 取值：

- `reveal`
- `copy`

`access_result` 取值：

- `allowed`
- `denied`

## 7. 密钥生命周期

### 7.1 状态机

密钥状态定义为：

- `active`
- `expiring`
- `expired`
- `disabled`

状态规则：

1. 新建后默认 `active`
2. 距离 `expires_at` 小于等于 3 天时标记为 `expiring`
3. 到达 `expires_at` 后自动转 `expired`
4. 手工停用转 `disabled`
5. `expired` 和 `disabled` 都不能继续调用

### 7.2 默认值

- 创建时默认 `expires_at = now() + 30 days`
- 控制台允许 admin 后续扩展修改有效期，但第一版 member 不自定义

### 7.3 轮换规则

轮换时：

1. 新建一个新的 key 记录
2. 旧 key 立即转 `disabled`
3. 新 key 继承原 key 的：
   - `tenant_id`
   - `scopes`
   - 生命周期默认值重新开始计算
4. 写入：
   - `rotated_from_key_id`
   - 审计事件

## 8. 权限与回显边界

### 8.1 member 权限

`member` 可以：

- 查看自己创建的密钥列表
- 选中自己创建的密钥后查看明文
- 复制自己创建的密钥明文
- 创建、轮换、停用自己创建的密钥

`member` 不可以：

- 查看同租户其他成员创建的历史明文
- 复制同租户其他成员的历史明文

### 8.2 admin 权限

`admin` 可以：

- 查看任意租户的任意平台密钥
- 查看和复制历史明文
- 停用、轮换任意密钥
- 查看所有密钥回显审计记录

### 8.3 安全策略

回显能力必须满足：

1. 服务端实时校验权限，不依赖前端隐藏
2. 每次“显示完整密钥”都写审计
3. 每次“复制完整密钥”也写审计
4. 返回明文时不进入通用列表接口，必须走单独的受控接口

## 9. 控制台交互设计

### 9.1 `member / API 密钥` 页面重构

页面改为三栏语义，但可以在移动端纵向折叠：

1. `密钥列表区`
2. `已选中密钥详情区`
3. `新建 / 轮换 / 停用操作区`

### 9.2 已选中密钥详情区

当用户选择某个密钥时，必须稳定显示：

- 名称
- 状态
- 权限范围
- 创建时间
- 到期时间
- 最近使用时间
- 创建人
- 所属租户

如果当前用户有明文查看权限，还要显示：

- `显示完整密钥` 按钮
- `复制完整密钥` 按钮
- 默认展示脱敏明文
- 点击显示后再展示完整明文

如果当前用户没有查看权限：

- 不显示“显示完整密钥”
- 不显示“复制完整密钥”
- 显示只读提示：
  - `该密钥由其他成员创建，出于安全限制，不能查看历史明文。`

### 9.3 明文展示策略

不建议“选中即直接把完整明文渲染在页面上”。

推荐交互：

1. 选中密钥
2. 先看到脱敏摘要
3. 点击 `显示完整密钥`
4. 前端请求受控接口
5. 成功后在当前卡片内短时展示完整明文
6. 同时提供 `复制完整密钥`

原因：

- 降低误暴露风险
- 审计动作更明确
- 更像成熟控制台，而不是直接把 secret 裸露在列表页

### 9.4 创建结果体验

创建或轮换成功后：

- 按钮立即进入 `创建中...` 或 `轮换中...`
- 成功后自动滚动到结果卡片
- 结果卡片默认显示：
  - 新密钥名称
  - 当前状态
  - 到期时间
  - 脱敏明文
  - `显示完整密钥`
  - `复制完整密钥`

这部分不是一次性提示，而是与“选中密钥详情区”合并，避免出现两套割裂 UI。

### 9.5 租户额度卡片

在 member 的 `我的总览` 和 `API 密钥` 页面顶部增加额度卡：

- 本周期请求额度
- 已用请求数
- 剩余请求数
- 本周期 Token 额度
- 已用 Token
- 剩余 Token
- 周期重置时间
- 当前是否进入告警态

### 9.6 即将过期提示

当密钥进入 `expiring`：

- 列表状态显示 `即将过期`
- 详情区显示：
  - `该密钥将在 3 天内过期，请尽快轮换`

### 9.7 admin 视图补充

admin 的密钥页比 member 多看见：

- 创建人
- 历史回显记录次数
- 最近一次回显时间
- 最近一次复制时间

## 10. 后端接口设计

### 10.1 密钥列表接口

保留：

- `GET /api/me/api-keys`
- `GET /api/admin/api-keys`

列表返回字段新增：

- `created_at`
- `expires_at`
- `created_by_user_id`
- `created_by_name`
- `can_reveal`
- `lifecycle_status`

说明：

- 列表接口不返回完整明文
- 只告诉前端该 key 当前是否允许回显

### 10.2 受控回显接口

新增：

- `GET /api/me/api-keys/:id/secret`
- `GET /api/admin/api-keys/:id/secret`

返回：

- `raw_key`
- `masked_key`
- `revealed_at`

服务端行为：

1. 校验权限
2. 解密 `key_ciphertext`
3. 写入 `api_key_secret_access_logs` 与 `audit_events`
4. 返回明文

### 10.3 复制事件接口

新增：

- `POST /api/me/api-keys/:id/secret/copy`
- `POST /api/admin/api-keys/:id/secret/copy`

作用：

- 前端点击复制成功后上报一次审计事件

说明：

- 浏览器本地复制动作无法完全由服务端感知
- 因此采用“前端复制成功后回传记录”的方式

### 10.4 创建与轮换接口返回

保留当前返回结构，但补充：

- `expires_at`
- `lifecycle_status`
- `can_reveal = true`

### 10.5 租户额度接口

新增：

- `GET /api/me/quota`
- `GET /api/admin/tenants/:tenant_id/quota`

返回：

- `period_type`
- `period_start`
- `period_end`
- `request_limit`
- `requests_used`
- `requests_remaining`
- `token_limit`
- `tokens_used`
- `tokens_remaining`
- `is_near_exhausted`
- `is_exhausted`

## 11. 网关额度拦截设计

### 11.1 拦截时机

请求经过 API Key 鉴权并解析出 `tenant_id` 后，进入额度判断。

顺序：

1. 校验密钥状态是否可用
2. 校验密钥是否过期
3. 校验租户请求数额度
4. 校验租户 token 额度
5. 通过后继续转发

### 11.2 请求次数额度

每次成功到达平台入口的有效调用，都计入 `requests_used`。

### 11.3 Token 额度

Token 口径沿用当前项目已存在的“上游 usage 优先，本地估算兜底”模型。

额度消耗按最终 `total_tokens` 结算。

### 11.4 超限行为

请求数超限：

- 返回 `429`
- 错误文案：`当前租户请求额度已用尽`

Token 超限：

- 返回 `429`
- 错误文案：`当前租户 Token 额度已用尽`

### 11.5 周期重置

第一版固定月度周期：

- 每月 1 日零点按租户时区重置
- 或者统一按 `Asia/Shanghai` 重置

为降低复杂度，第一版直接统一按 `Asia/Shanghai`。

## 12. 审计与可观测性

### 12.1 审计事件新增类型

新增：

- `api_key_secret_revealed`

- `api_key_expiring_warning`
- `api_key_expired`
- `tenant_quota_exhausted_requests`
- `tenant_quota_exhausted_tokens`

### 12.2 member 侧审计展示

member 只看到与自己相关的事件：

- 自己创建了密钥
- 自己轮换了密钥
- 自己查看了密钥明文
- 自己复制了密钥

### 12.3 admin 侧审计展示

admin 看到：

- 所有密钥明文访问记录
- 所有租户额度超限事件
- 所有过期与告警事件

## 13. 加密与安全实现

### 13.1 存储方式

平台 API Key 明文不直接落库。

存储规则：

- 明文生成后立即加密
- 数据库存：
  - `key_hash`
  - `key_ciphertext`

### 13.2 加密密钥

使用平台运行时主密钥：

- 从环境变量或 secrets 文件加载
- 不提交到 git
- 支持 `key_kek_version`

### 13.3 服务端要求

- 解密逻辑仅存在于 gateway 服务端
- 不在前端、Nginx 或日志中输出明文
- API 响应默认不打印 raw secret 到服务日志

### 13.4 风险接受

既然产品选择了“历史密钥可回显”，就必须接受：

- 平台具备查看用户平台 API Key 明文的能力

所以安全要求要从“完全不可回显”转为：

- 最小授权
- 审计可追踪
- 加密存储
- 明文不进入普通日志

## 15. 迁移与兼容

### 15.1 老数据处理

当前库里已有的历史 key 只有 hash，没有密文。

这些老 key 无法被平台回显。

因此需要兼容状态：

- `legacy_unrecoverable = true`

对于老 key：

- 仍可继续鉴权
- 但控制台不显示“显示完整密钥 / 复制完整密钥”
- 提示：
  - `该密钥创建于旧版本，平台无法恢复历史明文，请轮换后使用新密钥。`

### 15.2 新数据规则

从本设计落地后创建的新 key：

- 必须同时写入 `key_hash + key_ciphertext`

## 16. 测试要求

### 16.1 后端测试

必须新增：

- 密钥加密存储与解密测试
- member 只能回显自己创建密钥的权限测试
- admin 可回显任意密钥测试
- legacy key 不可回显测试
- 30 天过期与 3 天告警状态测试
- 请求数超限测试
- token 超限测试

### 16.2 前端测试

必须新增：

- 选中可回显密钥时显示“显示完整密钥 / 复制完整密钥”
- 选中不可回显密钥时不显示复制按钮
- 创建后展示到期时间和结果区
- member 配额卡展示
- 过期告警文案展示

### 16.3 集成测试

至少覆盖：

1. 创建新密钥
2. 回显历史明文
3. 复制并记审计
4. 超额请求被拒绝
5. 过期密钥请求被拒绝

### 阶段 2：补回显与权限
